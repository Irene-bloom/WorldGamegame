# 小径分岔的花园 · The Garden of Forking Paths

一个基于博尔赫斯同名短篇的解谜探索游戏原型。

> 时间不是一条直线，而是一张**分岔的网**。每个抉择点，所有结局同时发生，各自分裂出新的时间线（「若干」未来，并非全部）。
>
> 你继承了曾祖父崔朋留下的「花园」——它不是园林，是一座用时间砌成的迷宫。一部谁也读不完的小说，和一座谁也走不出的迷宫，原来是同一件东西。
>
> 要抵达花园的「中心」，你必须学会**侧耳倾听邻近的时间线**，从「另一个你」的命运里，推断出自己该怎么走。

---

## 核心机制：跨线观察推理

这是本作区别于普通分支叙事游戏的地方。

任何单一时间线里的信息都不完整。在花园的某些**观察点**，你能窥见**邻近时间线**里发生的事——比如「另一个你推开左门，被落石压死」。用这些信息，反推出你**这条**线该怎么选。

- **盲猜必死**：不去观察邻近线，关键岔路就只能瞎蒙，而错误的路通向死亡。
- **观察即解谜**：窥见邻近线的命运后，正确答案才浮现；某些进阶岔路甚至**必须先观察到对应线索才会解锁**。
- **死亡不是终点**：走入死路只是退回上一个分岔点，换一条时间线重走——因为所有时间线本就并存，你只是切换了观察的视角。死路会在分岔网上标记为「已知废墟」。

## 玩法一览

- **时间分岔网**（左上）：一张 SVG 绘制的网，节点是事件场景。青色=当前线，琥珀=邻近线，紫色=中心，灰色✕=死路。只显示你「已知」的部分，其余隐入迷雾。点击任意已知节点可「跳读」其叙事（不影响进度）。
- **叙事与选择**（左下）：阅读当前场景，做出选择，推动时间线分岔。
- **侧耳倾听**（右）：在观察点窥见邻近线的命运，收集线索。

第一关《两扇门与一口井》含 2 个核心谜题：一个入门（看死讯避开陷阱门），一个进阶（识破假井、找到暗格——且该选项被观察线索门控）。

## 技术栈

- **Next.js 15 + React 19 + TypeScript + Tailwind CSS**
- 纯前端，进度存 localStorage，无需后端
- **第一版纯静态**：所有场景、选择、线索预先写死，保证谜题逻辑严密、可解、离线可玩
- 架构预留 AI 接口（`lib/narrator.ts`），以后可让 AI 在不改变谜题逻辑的前提下润色叙事

## 本地运行

```bash
npm install
npm run dev
```

打开 http://localhost:3000 。

> 注：若 3000 端口被占用，Next 会自动换端口（看终端输出），或用 `npm run dev -- -p 3100`。

## 验证（端到端通关测试）

```bash
npm run verify
```

在纯函数引擎上模拟玩家完整通关，断言：正确路径可达中心、两条死路可回溯、以及「不观察邻近线就走不到正解」的机制证明。改了 `lib/story.ts` 的关卡数据后，跑这个能立刻确认没把关卡改成死局。

## 代码结构

```
lib/
  story.ts        # 时间分岔图数据模型 + 第一关数据 + 取边函数（加内容=加数据）
  game-state.ts   # 游戏状态 + localStorage 存取 + 引擎纯函数（选择/观察/回溯/门控）
  narrator.ts     # 叙事润色接口（预留 AI）
components/
  ForkGraph.tsx   # SVG 时间分岔网可视化
  NodePanel.tsx   # 节点叙事 + 选择 + 回溯
  ObservePanel.tsx# 跨线观察（核心机制 UI）
app/
  page.tsx        # 把以上串成可玩游戏
scripts/
  verify.ts       # 端到端通关验证
```

## 如何扩展

- **加关卡 / 加节点**：编辑 `lib/story.ts` 的 `LEVELS`。一个节点写清楚 `choices`（分岔）和 `observe`（可窥见的邻近线），引擎和可视化会自动接管。用 `requiresObserved` 制造「必须先观察才能走」的进阶谜题。
- **接 AI 润色**：把 `lib/narrator.ts` 的 `narrateNode` 改成调用 Anthropic SDK（文件里有注释示例），其余代码无需改动。
